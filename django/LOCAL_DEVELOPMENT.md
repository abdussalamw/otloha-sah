# بيئة تطوير محلية مستقلة لاتلوها صح

> **الغرض:** تشغيل QuranAPI وOtlohaSah محلياً، بقاعدتي بيانات منفصلتين عن الإنتاج، لتطوير الواجهات وAPI والميزات دون الحاجة إلى بيانات الاستضافة القديمة أو التأثير على المستخدمين الحاليين.

## ما الذي أصبح متاحاً في المستودع؟

أضيفت قوالب بيئة تطوير محلية ومشغّل واحد للخدمتين:

| العنصر | المسار | الوظيفة |
|---|---|---|
| قالب QuranAPI | `django/QuranAPI/.env.local.example` | إعداد محلي لـ SQLite وHTTP وCORS. |
| قالب OtlohaSah | `django/OtlohaSah/.env.local.example` | إعداد محلي مستقل يربط QuranAPI على المنفذ 8001. |
| مشغّل التطوير | `django/scripts/local-development.sh` | يثبت الاعتمادات ويطبق migrations ويشغّل كل خدمة. |
| قالب Flutter | `flutter/Otloha-Sah-Flutter/.env.development.example` | يوجّه نسخة التطوير إلى الخوادم المحلية. |

ملفات `.env` و`.env.local` وملفات SQLite مستبعدة من Git عمداً، ولا يجوز وضع أسرار الإنتاج فيها.

## المتطلبات

يلزم على جهاز التطوير Ubuntu/macOS أو WSL مع الأدوات التالية:

| الأداة | الاستخدام |
|---|---|
| Git | جلب المستودع والتحديثات. |
| Python 3.12 | تشغيل خدمتي Django. |
| `uv` | إنشاء البيئات الافتراضية وتثبيت ملفات القفل. |
| Flutter SDK | تشغيل تطبيق الجوال على محاكي أو هاتف. |

Redis غير مطلوب لتصفح HTTP وتطوير الواجهات الأساسية. أضفه عند اختبار Celery أو WebSockets أو الإشعارات الحية.

## تشغيل Django محلياً

من جذر المستودع، نفّذ الأمر التالي مرة واحدة بعد كل تغيير كبير في الاعتمادات أو migrations:

```bash
./django/scripts/local-development.sh setup
```

ينشئ هذا الأمر بيئتين افتراضيتين ويطبق migrations على قاعدتي SQLite مستقلتين. لا ينسخ بيانات الإنتاج ولا يتصل بها.

بعد ذلك، افتح نافذتي طرفية منفصلتين:

```bash
# النافذة الأولى: QuranAPI
./django/scripts/local-development.sh run-quran
```

```bash
# النافذة الثانية: OtlohaSah
./django/scripts/local-development.sh run-otloha
```

تكون الروابط المحلية هي:

| الخدمة | الرابط |
|---|---|
| QuranAPI | `http://127.0.0.1:8001` |
| OtlohaSah | `http://127.0.0.1:8000` |
| قراءة التلاوات محلياً | `http://127.0.0.1:8001/api/v1/narrations/` |
| مستويات التجويد محلياً | `http://127.0.0.1:8000/api/v1/tajweed/levels/` |

لفحص الإعدادات دون تشغيل الخوادم:

```bash
./django/scripts/local-development.sh check
```

## تشغيل Flutter على بيئة التطوير

انسخ القالب إلى ملف البيئة الذي يقرأه Flutter:

```bash
cd flutter/Otloha-Sah-Flutter
cp .env.development.example .env
```

ثم عدّل العناوين بحسب نوع الجهاز:

| الجهاز | `TESTING_BASE_URL` | `QURAN_API_BASE_URL` |
|---|---|---|
| Android Emulator | `http://10.0.2.2:8000` | `http://10.0.2.2:8001` |
| iOS Simulator أو سطح المكتب | `http://127.0.0.1:8000` | `http://127.0.0.1:8001` |
| هاتف حقيقي | `http://LAN_IP:8000` | `http://LAN_IP:8001` |

على هاتف حقيقي، شغّل الخدمتين مع عنوان الشبكة بدلاً من `127.0.0.1`:

```bash
./django/scripts/local-development.sh run-quran 0.0.0.0 8001
./django/scripts/local-development.sh run-otloha 0.0.0.0 8000
```

ثم استبدل `LAN_IP` بعنوان جهاز التطوير على الشبكة نفسها، مثل `192.168.1.50`. لا تستخدم هذا الربط خارج الشبكة الخاصة، ولا تفتح المنفذين إلى الإنترنت.

عند `APP_ENV=development`، يفعّل التطبيق وضع الاختبار تلقائياً. كما يقرأ قارئ القرآن `QURAN_API_BASE_URL` بدلاً من تثبيت نطاق الإنتاج في الكود.

## البيانات المحلية مقابل بيانات الإنتاج

قاعدة التطوير تبدأ فارغة عمداً. وهي صالحة لتطوير التسجيل والدخول والنماذج والواجهات والاختبارات، لكنها لا تتضمن تلقائياً المصاحف أو القراء أو التلاوات أو الترجمات أو التفسير الموجود في الإنتاج.

> لا يمكن إنشاء نسخة مطابقة من بيانات الإنتاج دون أحد المصادر التالية: نسخة احتياطية لقاعدة البيانات، تصدير بيانات مصرح به من الشركة، أو بيانات محتوى مستقلة مرخصة للاستيراد.

عند حصولك على نسخة احتياطية، يجب استيرادها إلى **بيئة تطوير منفصلة فقط** بعد إخفاء بيانات المستخدمين وكلمات المرور والرموز والملفات الحساسة. لا تستورد بيانات إنتاج حية إلى جهاز تطوير غير محمي.

إلى أن تتوفر البيانات، يمكننا تجهيز مجموعة بيانات قرآنية تجريبية صغيرة لتطوير الشاشات، ثم إجراء اختبار استيراد منفصل للمحتوى الكامل عندما يتاح مصدر معتمد.

## عند توفر استضافة بديلة

يمكن نقل هذا التكوين نفسه لاحقاً إلى نطاق اختبار مستقل، مثل `api-staging.example.com` و`staging.example.com`. عندها يجب استخدام PostgreSQL وRedis منفصلين وشهادة TLS صالحة، مع قاعدة بيانات اختبار فقط. لا تربط التطبيق التجريبي بقاعدة بيانات الإنتاج.

## عند استلام بيانات الاستضافة القديمة

لا تغيّر الإنتاج مباشرة. أولاً، قارن إعداداته مع هذه البيئة، خذ نسخة احتياطية، وجدّد TLS، ثم انقل الإصلاحات تدريجياً بعد اختبارها على بيئة Staging. تبقى البيئة المحلية الحالية هي مكان تطوير الميزات واختبارها بأمان.
